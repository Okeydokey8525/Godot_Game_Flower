### Engine-migration interpretation

The current runtime source is a preserved GDevelop 5 folder project. ADR-006 selects
Godot 4.7.1 Standard with GDScript and the Compatibility renderer as the target
production runtime. The Python benchmark is not game-engine runtime evidence and does
not certify a Godot content loader, FPS, frame time, draw calls, boot, scene loading,
or runtime RAM. All GDevelop-runtime wording below is historical context, not a Godot
PASS claim.

The benchmark reads the frozen 55-entry content manifest in manifest order. It uses
`time.perf_counter_ns`, 20 warm-ups plus 100 measured file-I/O iterations, and 50
warm-ups plus 500 measured in-memory iterations. Raw samples and metadata are stored
in `Source/Data/Reports/performance_raw_samples.json`; statistical summaries are in
`Source/Data/Reports/performance_report.json`.

File-I/O results are **not** cold-cache results: `os_cache_state` is `uncontrolled`.
All reported Python timing supports the data pipeline only and cannot certify
GDevelop `ContentManagerSystem`, FPS, frame time, draw calls, boot, scene loading,
or runtime RAM.

flower instances, and a two-slot inventory. It is structurally representative of

## Budget interpretation

The budget numeric targets were not changed. Its definitions now state that JSON
runtime load, registry runtime RAM, boot, scene loading, draw calls, active/visible
object scenarios, and frame performance all require GDevelop runtime evidence.

The project currently has no `MainMenuScene`, so the boot-to-menu endpoint is
unresolved. `StressTest.json` contains 12 flower instances, not 500. Neither may be
treated as a passing runtime scenario.

## Future M4.2C-B instrumentation specification — not implemented

When an executable GDevelop build is available, add a debug-only capture system only
after API validation. It must require an explicit capture-enable flag; collect named
markers (`boot_first_frame`, `greenhouse_ready`, `scene_transition_requested`,
`scene_ready`); retain raw frame-delta and active-object samples; collect visible
objects only when the API is validated; and run normal/100/250/500-flower scenarios
for at least 300 seconds. Each export needs run metadata, scenario, build type,
resolution, sample count, and an explicit failure state if export is unavailable.

No GDevelop event JSON or `Source/game.json` registration was created in M4.2C-A.

## Integrity and limitations

The benchmark calculated SHA-256 snapshots before and after execution. All 60
content JSON files and the frozen economy-anchor document were unchanged during the
run. Git commit metadata is unavailable in this workspace; hardware RAM is also
unavailable in the sandbox and is recorded as such in raw metadata.

M4.2C-A can PASS because its reproducible Python evidence exists. M4.2C-B remains
PENDING. The overall milestone is therefore PARTIALLY COMPLETE, not a full
performance-validation PASS.
